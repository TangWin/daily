Agent Autoloop：让 Claude Code / Codex 在后台自己接活，拿不准才发卡片问你

为什么今天值得试： 11 月 3 日刚开源，两天 2600+ 星、500+ fork，今早（北京时间 09:56）刚发 v1.1.1，作者一晚上合了十几个稳定性修复。它补的正是命令行 Agent 最缺的一块：人走开后事情还能接着办完。

仓库：KKKKhazix/agent-autoloop

它解决什么问题 / 适合谁

平时用 Claude Code、Codex 都得守着终端，关窗口或人走开事情就断了。Agent Autoloop 是一个装在自己 Mac / Linux 上的轻量自动化中台：定时任务、GitHub Issue、告警等事件进来后，按你写的规则派给本机已登录的命令行 Agent 干活；遇到删数据、重启、花钱、对外发消息这类拿不准的事，就把卡片推到飞书、钉钉、企微、Slack、Discord 或桌面通知等你拍板，你选完它接回原会话继续干。

适合：已经在用命令行 Agent、想让它每天自动写早报、跟进 Issue、巡检网站、排查告警的个人开发者和小团队。

从 README 读到的要点

  • 一份 rules.json 就能派活： 写清「什么事、交给谁、在哪个目录干」，支持 cron 和外部事件，保存几秒内生效；规则写坏了会继续按旧规则跑并提醒你。
  • Agent 只需一个约定： 在最后一条回复里交代结果；要请示就在末尾附一段 agent-autoloop 代码块，可提问（ask）、通知（notice）、关卡片（resolve）、预约复查（later）、触发新事件（events）。
  • 挂起零消耗： 等你回复时 Agent 进程直接退出，不占进程、不花 Token，回答后续接原会话。
  • 插件四个方向可换： 事件（GitHub/GitLab Webhook、HTTP、定时）、Agent（Claude Code、Codex、ACP、通用命令，DeepSeek Harness、pi、Hermes、Cursor CLI 等一行接入）、通道、交付（PR 打 deliver 标签后审代码、等 CI、合并、核对线上版本）。
  • 内核很克制： 约 1650 行、零运行时依赖，事件溯源（agent-autoloop why 1 查任意一轮来龙去脉）、外部文字不拼进提示词、超过 8 层自动熔断。
  • 现成场景模板： 每日早报、跟进 Issue、线上告警、用户反馈、网站巡检、飞书周报。

近期活跃证据

  • Release： 两天发了 3 版，v1.0.0（11-04 05:58 北京时间）、v1.1.0（插件出错不拖垮中台、失败 10 次停止重试等），v1.1.1（11-05 09:56，修复重派时重做业务）；从 v1.1.0 起安装与更新只跟 Release。
  • 提交： 建库以来约 77 次提交（作者约 60 次），今天凌晨到早上仍在持续合并测试、变异检查和稳定性修复。

怎么快速上手

  1. 准备 macOS 或 Linux，装好 Node 24、Git、curl，以及一个已登录的 Claude Code 或 Codex。
  2. 运行 curl -fsSL https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.sh | sh。
  3. 运行 agent-autoloop try 走一遍「提问、退出等回复、拍板、接着干完」，再用 agent-autoloop status 看轮数、Token 和费用；之后在 ~/.agent-autoloop/rules.json 里加一条每日早报规则试试。

风险与注意

  • 暂无 Windows 版： 作者说 11 月 7、8 日周末开发，进度见 #17。
  • 项目才两天： 迭代极快，配置和行为可能频繁变化；钉钉/企微/Slack/Discord 模板只在本地模拟服务上验证过，GitLab 未连真实实例。
  • 额度与合规： 跑的是你自己的账号；高频自动化下厂商更建议用 API Key，个人订阅额度可能吃紧。
  • 权限： 它会让 Agent 无人值守地在本机目录里改代码、跑命令，规则里的目录和权限要自己把好关。
