openset-llm：没有显卡、8GB 内存的普通 x86 机器上，以 17–20 tok/s 跑 27B 模型

为什么今天值得试： 想在本地跑一个够用的大模型，通常得有 24GB 以上显存，或者 32GB 内存的机器。openset-llm 给 PrismML 的三值（ternary）Bonsai-2-27B（Qwen3.8-27B 压到 5.95GB）写了一套新的 AVX-512/AVX2 内核，再接上模型自带的多 token 预测头做投机解码，并让 Agent 循环能接着上一轮继续算。作者在 8 vCPU / 8GB 内存、没有 GPU 的 Ice Lake 云主机上实测 17–20 tok/s，是同机 ik_llama.cpp 的约 4.3 倍。它提供 OpenAI 兼容接口，现有 Agent 改个 base_url 就能用。昨天（北京时间 11-27 到 11-28 凌晨）一天连发 v0.3.0→v0.3.4 共 5 版：没有 AVX-512 的笔记本/台式机能跑了，还有一条命令安装、预编译引擎和容器镜像，今天上手门槛最低。

  • 仓库：https://github.com/opensetlabs/openset-llm
  • 许可证：MIT（保留 ggml 版权；模型权重 Apache-2.0，从 Hugging Face 下载）；主语言 Python（引擎是 C/C++ 补丁）；2214★ / 213 fork；2026-11-13 20:45 北京时间建库，公开 git 历史从 11-21 的「Initial release」开始

解决什么问题、适合谁

  • 手上只有普通 Linux 服务器、云主机、WSL2 笔记本，想要一个不按 token 收费的本地 27B 模型，给 Agent、信息抽取、搜索或 RAG 用
  • 想在便宜的 8 vCPU / 8GB 云主机上自建 OpenAI 兼容接口，评估纯 CPU 推理成本的人
  • 对三值量化内核、MTP 投机解码、前缀状态续算这些推理优化感兴趣，想看一套带完整基准、能复现的工程实现

README 里的关键能力

  • 速度（作者实测）： 8 vCPU / 8GB Ice Lake 上 ./serve 默认 19.67 tok/s，关掉投机解码约 10 tok/s；ik_llama.cpp 4.58、PrismML 分支 2.72；Zen 4 上 21.1，Zen 5 上 35–36 tok/s
  • 质量没掉： 加速前后 GSM8K-40 都是 39/40，代码 pass@1 83.1% 对 83.8%（p=1.0），WikiText-2 困惑度 7.5702 对 7.5699；三值模型本身和全精度模型的差距要看 PrismML 的模型卡
  • Agent 循环续算： 客户端每一步只改提示词结尾时，服务端从分叉处接着算，不重读整段；16k 上下文每一步约 55 秒，ik_llama.cpp 要 314 秒，回复逐字节相同
  • --multi N 多路并发： 4 路总吞吐是单路的 2.3 倍；多个 Agent 共用的 system prompt 和工具列表只读一次、存到磁盘
  • 长上下文： 默认 4k；--kv8/--kv6/--kv5 压缩注意力缓存（实验性，8GB 下最长 32k/64k）；还能用 -- --lora 挂 Qwen3.8-27B 的 GGUF LoRA（实验性）
  • 硬件路线： AVX-512 VNNI+VBMI（Ice Lake 以后的 Xeon、Zen 4/5、Ryzen 7000/9000）速度最快；只有 AVX2 的 CPU（Intel 12 代以后的酷睿、Zen 1–3）走 256 位内核，纯解码 6–8 tok/s；ARM 只能编译，没测过；Apple Silicon 请用 PrismML 的 Metal 版
  • 可复现： bench/ 里有固定版本的对手构建和交替跑的脚本；./bench/quick.sh --plain 约 5 分钟出一份能直接贴进 Issue 的测速报告

快速上手

  1. 先确认 CPU 走哪条路径：grep -m1 '^flags' /proc/cpuinfo 里有 avx512_vnni 和 avx512vbmi 就是最快路径；clone 下来后也可以跑 ./install.sh --check，它会同时检查内存（至少 8GB 可用，安装时要约 15GB 磁盘）
  2. 一条命令安装：curl -fsSL https://raw.githubusercontent.com/opensetlabs/openset-llm/main/get.sh | bash，再运行 openset-llm，会下载约 7.3GB 模型并打开 http://127.0.0.1:8080 聊天页（建议先读一遍 get.sh）；也可以用 Docker：docker run --rm -p 127.0.0.1:8080:8080 -v openset-llm-models:/data/models ghcr.io/opensetlabs/openset-llm
  3. 接 Agent：把 OpenAI 客户端的 base_url 设为 http://127.0.0.1:8080/v1、model="openset-llm"；多个 Agent 一起用就改跑 ./serve --multi 4，只要 API 用 --no-webui

风险 / 注意点

  • 只支持一个模型： 目前只有 Bonsai-2-27B 三值版，还没有更小的模型；内存低于 8GB 安装脚本直接拒绝。默认 4k 上下文，8GB 机器上默认配置只剩约 0.2GB 空闲内存，跟别的程序一起跑容易 OOM
  • 数字都来自作者的云主机： 一般云主机的 8 vCPU 其实只有 4 个物理核，速度会更低；AVX2 路径没在真实的笔记本/台式机芯片上测过（只用关掉 AVX-512 的服务器和模拟器验证过）；大小核 CPU、ARM 都没测
  • 项目很新，发版很快： 公开历史只有一周，一天发 5 版；安装脚本要下载约 7.3GB 并在本机编译或打补丁，#146 说明模型下载的完整性检查还在补
  • 社区热度要打折看： 有一批模板化的新账号 Issue/PR，部分维护者回复由 AI 生成；star 数不一定代表真实用户量，以自己机器上 bench/quick.sh 的实测为准
  • 服务默认不鉴权： Docker 示例只绑定 127.0.0.1；要对外提供服务，请自己在前面加带鉴权的反向代理
