rust-anything：让 Coding Agent 把你的应用一块块改写成 Rust，每一步都对照原版验证

为什么今天值得试： 让 Agent 把代码"翻译成 Rust"不难，难的是证明改完行为没变。rust-anything 自己不翻译代码。它先录下原程序在大量边界输入上的真实输出，再逐个函数、逐个模块地用这些录制结果检查 Rust 版本，全部对上才算完。它带 MCP 服务器和 skill，Claude Code、Codex、Cursor、Gemini CLI 都能直接用。项目北京时间 11-16 建库，两天发了 6 个版本，最近 24 小时有 83 次提交，外部 Issue 和 PR 大多当天就合并或修掉。

  • 仓库：https://github.com/erkamyaman/rust-anything
  • 许可证：MIT；主语言 Rust；1399★ / 93 fork；最新 v1.4.0（2026-11-18 09:23 北京时间），crates.io 和 npm 都能装

解决什么问题、适合谁

想把 Node.js/TypeScript、Python、C、Go、Ruby、Java 项目整体或部分迁到 Rust，又怕改出回归的人。也适合只想把某个慢的热点（搜索、slugify、解析之类）挪到 Rust 提速的人。还有一类人会感兴趣：想看怎样给 Coding Agent 一套"可验证的完成标准"，而不是让它说一句"我改好了"就算数。

README 里的关键能力

  • 一条闭环： profile（用各语言自己的 profiler 找热点和调用方）→ analyze（拆单元、排移植顺序、列出风险对应的 file:line、给依赖找对应的 crate）→ bridge（生成 napi-rs/wasm/PyO3/cgo/JNI/magnus 绑定和待填的 port.rs，调用方 API 不变）→ record（在非 ASCII、emoji、-0、NaN、溢出、有符号除法、map 顺序等陷阱输入上跑原程序，存成 cases.jsonl）→ diff / bench → shadow（线上两边同时跑，返回原版结果并上报不一致）→ gate
  • gate 很严： fmt、clippy -D warnings、测试、unsafe 审计、不能留没移植的部分；原程序的每条错误路径都要有一条录下来的失败用例；原版会返回错误的地方不许用 unwrap/panic!；Rust 代码行数超过原版 3 倍也不过
  • 整个应用迁移： app record / app replay 把 CLI 或 HTTP 服务器当黑盒录制和回放（trycmd 格式，可以手改）。app front-door 先用 Rust（clap 或 axum）接管入口，没移植的命令和路由转发给原程序；app wire 每次接一个单元，同时统计回退率；回退率降到 0、所有单元都过 gate 后，app lift 去掉原程序，变成纯 Rust。配套的 whole-app skill 会让 Agent 先逐轮问清决策并写成 ADR，用 MAP.md/HANDOFF.md 支持跨会话、多个子 Agent 并行
  • 讲实话的性能数据： 批量模式（--batch）把整个循环搬到 Rust、在多核上跑。x18n 的 5 万键搜索从 10ms 降到 0.5ms（20 倍），Python slugify 快 17 倍，Go 快 4 倍，Java 快 3 倍。README 也直说：逐个调用的小函数移植后往往比 JIT 更慢，x18n 核心 29 个函数全过了 gate，但实测比 TS 慢。所以上线前先看 bench
  • 语言： TS/JS、Python、C、Go、Ruby、Java 完整支持；PHP、C# 是预览，目前只能录制和回放整个应用，接 front door
  • 本地运行： 不上传代码。setup 改 Agent 配置前会先备份成 .rust-anything.bak，--remove 可以撤销

快速上手

  1. cargo install rust-anything（需要 Rust 1.97 及以上；也可以 npm install -g rust-anything 或从 Release 下载预编译二进制），然后运行 rust-anything setup，把 MCP 和 skill 注册进你的 Agent
  2. 在项目里先跑 rust-anything profile . -- <你的基准命令> 和 rust-anything analyze .，看热点和推荐先移植的单元
  3. 对 Agent 说："This search feels slow. Profile it with rust-anything and move the hot loop to Rust." 让它走完 bridge → record → diff → bench → gate；gate 过了、bench 确实变快了再上线

风险与注意点

  • 非常新： 建库才两天，作者一人写了大部分代码，版本发得很密，CLI 和行为可能还会变。star 涨得快，长期维护情况还要看
  • 只能证明录制覆盖到的行为： 时间、内存、并发、网络和数据库副作用不比较；正则在非 ASCII 文本上、浮点数格式化、跨平台差异都可能漏过去。README 有专门一节"What it can't catch"，用之前要读
  • 不一定更快： 逐个调用的小函数经过桥接层反而会变慢，要用 --batch 并以 bench 结果为准；本来就稳定的 C 和硬件相关代码，analyze 也会建议留在 C
  • 环境和权限： 需要 Rust 加上源语言的运行时；setup 会改 ~/.claude.json、~/.codex/config.toml 等全局配置（有备份），在意的话可以手动加 rust-anything mcp；整个应用迁移的 skill 会让 Agent 跑很久，额度消耗不小
