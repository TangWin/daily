gputaskman：看清显存里到底装了什么，是模型权重、KV 缓存还是浏览器

为什么今天值得试： Scott Hanselman（微软开发者社区的老面孔）11 月 3 日开源的终端工具，一周拿下约 1500 星。本地跑大模型最常见的困惑是「显存满了，但到底谁占的」：任务管理器和 nvidia-smi 只给一个总数，它能把显存拆到进程、运行时、模型文件，再把 llama.cpp / Ollama 的占用拆成权重、KV 缓存和计算缓冲区。昨天还一口气合并了 8 个 PR，加了 record 录制功能。

仓库：shanselman/gputaskman

它解决什么问题 / 适合谁

在自己电脑上跑 llama.cpp、Ollama、LM Studio、PyTorch 训练或 Unsloth 微调的人。它回答这些问题：这 15 GB 显存是哪个进程、哪个模型用的；改了上下文长度 -c 后 KV 缓存涨了多少；为什么有一大块 GPU 内存落在系统内存里（可能拖慢推理）。云端服务、纯 CPU 或 NPU 推理不在范围内。

从 README 读到的要点

  • 一个更懂 AI 的 htop： 终端界面（TUI）同时显示设备的显存、负载、温度、功耗、PCIe 流量和历史曲线，以及每个进程的显存、溢出到系统内存的部分（Spill）、引擎占用、加载的运行时（CUDA、HIP、Vulkan、ggml、ONNX Runtime 等）。
  • 模型拆解： 读 GGUF 文件头估算权重和 KV 缓存，配合 llama-server 的日志（-lv 4 --log-file）给出实际缓冲区大小，并探测本机的 /props、/slots、/v1/models、/api/ps 拿到上下文长度、忙碌槽位和 Ollama / LM Studio 的友好模型名。作者在 RTX 4080 SUPER 上对过账：Qwen3-0.6B 的权重和 KV 估算与运行时日志完全一致。
  • 每条结论都标证据： 模型识别标出 api、mapped、cmdline、installed 哪种来源，两种强证据才算「确认」；测不到的值显示 n/a（JSON 里是 null），不会伪装成 0。
  • 跨平台： Windows（NVIDIA / AMD，用 WDDM 计数器，GeForce 上 nvidia-smi 给不出的每进程显存它能给）、原生 Linux（NVIDIA、AMD、Intel i915）、WSL（从 Windows 宿主读计数器再匹配回 Linux 进程）、Docker 容器、Apple Silicon Mac。
  • 可脚本化： --once 文本快照、--json 机器可读，gputaskman diff before.json after.json 对比加载模型前后哪块内存涨了，gputaskman record 每秒往 JSONL 文件追加一次快照，适合记录整晚的训练或推理服务。

近期活跃证据

  • Issues： 共 15 个，已关 11 个、开放 4 个。Ollama 清单里 layers 为空导致崩溃的报告（#33）不到一小时就修好合并；多显卡支持（#7）从提出到 v0.3.3 发布用了三天，期间有多位用户贴出三卡、混合厂商的实测结果。维护方的回复由 Copilot 代理代 Scott 分诊，并会明说自己不是本人。
  • Release： 一周 7 个版本，最新 v0.3.4 发布于北京时间 2026-11-09 10:28，加了精简监控视图和 Windows 显卡禁用后重新启用的自动恢复；每版自动出 Windows x64/ARM64、Linux x64/ARM64 便携包，并发布到 PyPI。
  • 提交： 91 次提交、9 位贡献者（作者 69 次）；北京时间 11 月 9 日下午到傍晚连续合并了 AMD、Intel、macOS、内存与 CPU 面板等社区 PR，以及 record 命令。

怎么快速上手

  1. 有 Python 3.11+：uv tool install gputaskman（或 pipx install gputaskman）。没有 Python 的 Windows 用户直接从 Releases 下载便携 ZIP，解压后运行 gputaskman.exe。
  2. 先开一个模型（例如 ollama run qwen3:8b 或你自己的 llama-server），再运行 gputaskman，用上下方向键选中那个进程看拆解；按 ? 看每个指标的含义和局限。
  3. 想看改参数的影响：gputaskman --json > before.json，调整上下文长度并发一次请求后再导出 after.json，跑 gputaskman diff before.json after.json。

风险与注意

  • 早期实验软件： README 自己说设备和进程计数器是实测，分类和 GGUF 拆解是估算；滑动窗口注意力的模型（如 Gemma 3）KV 估算只是上限。
  • 很多组合没在真机验证： 双独显、Windows 多卡、Intel xe 驱动、AMD 新的归属规则都标了「未在硬件上验证」；Linux 和 WSL 上已在运行的进程归属只是推测（标 ?）。
  • 便携包未签名，Windows 可能弹出警告；macOS 目前只能从源码运行。
  • 隐私： 检查器、JSON 和录制文件会包含路径、命令行参数、模型名和本地端口，分享截图或日志前要先打码。它会向本机已监听的端口发 GET 请求做探测，若 llama-server 用 --api-key 启动会带上这个 key（不存储也不打印）。
