今日推荐：tigerless-labs/agent-memory。它让 Claude Code、Codex 等 Agent 共用一份本地长期记忆，存成纯 Markdown 文件，不需要任何 API key。北京时间 10 月 23 日凌晨还在合入修复，值得试一试。

解决什么问题、适合谁

Agent 一关掉会话，就把学到的东西全忘了。它适合同时用好几个编程 Agent、又想让它们记住项目决策和个人偏好的人。记忆都是文件，可以用 grep 搜，也能放进 git 管理。

README 里的要点

  • 每条记忆就是一个 Markdown 文件，这是唯一的数据来源。SQLite 索引只是缓存，删掉后运行 mem rebuild 就能重建，不丢任何东西，项目里有测试专门保证这一点。
  • 检索全在本地完成：用 BM25 全文检索，也可以再叠加向量检索。结果只返回文件路径和一句摘要，Agent 需要时再去读大纲或全文。
  • 会话结束或压缩上下文时，钩子会自动提炼记忆，并先把完整对话归档留底。
  • 有一个「睡眠」整理环节，会自动合并和更新记忆；删除只会生成提案，等你确认后才执行。用 recall --as-of 还能查某一天当时的记忆状态。
  • 运行 mem setup --host claude-code 或 --host codex 一键接入，加上 --mcp 也能走 MCP。作者在 LongMemEval 上的对比：用它 52.9%，不用记忆 5.8%（测试范围由作者自选）。

快速上手

  1. git clone https://github.com/tigerless-labs/agent-memory.git && cd agent-memory && uv sync --all-packages，再 export PATH="$PWD/.venv/bin:$PATH"（需要 Python 3.12+ 和 uv）。
  2. mem init，用 mem record ... 写一条，再 mem recall "..." 找回来。
  3. mem setup --host claude-code（或 codex），看到 status: READY 即接好。

注意点

  • 纯中文摘要目前会生成空文件名（#20，未修），摘要里带点英文。
  • Windows 修复 PR（#58、#61、#62、#97、#99）未合入，先在 Mac 或 Linux 上试。
  • 基本一人主力维护，有 46 个 PR 在排队。
  • 接入 Codex 需把记忆库目录加进沙箱可写目录，并确认一次信任钩子。
