  1. 事件

    Strands Agents 博客（11 月 9 日）：Amazon 内部一个超大规模工单系统原本用 Claude Sonnet 4.6 给工单打 20 类标签（长系统提示 + 输出 JSON）。两位工程师换成 Strands Decider（Gemma 4 E4B 底座的决策模型，不生成文本，只对给定选项输出概率和置信度），部署在 SageMaker ml.g5.xlarge 上，单次约 640 ms。实测：平均调用 4,215 ms → 897 ms，每单 token 6,724 → 2,010，输出从 170 token 变成 1 个。因为 Decider 窗口只有 4,096 token，他们把每个标签的长描述改写成一两句判定标准，再加一个「none」选项。切换时用 AppConfig 做 BEDROCK / DUAL / DECIDER 三档开关，在真实流量上并跑对比，回滚只需 45 秒改配置。还发现一个坑：JSON key 顺序不同会让输出概率最多偏移 0.19，现在统一排序 key。

    为什么值得关注

    这是「封闭选择题别用大模型」的一个有完整数字的生产案例；三档灰度开关和「key 顺序影响结果」这两个细节比结论本身更值得抄。HN 评论也提醒：这只适用于标签固定、量大、上下文能压到几千 token 的场景。

    工作中怎么用

    支付系统里的风控初筛、交易异常归类、客诉/工单路由、对账差异分类，都可以评估换成小型决策/分类模型；先按文中的 DUAL 模式在线并跑，用分歧样本做判定，再切流。对任何 LLM 判定接口，都应固定输入的 JSON key 顺序，保证可复现。

  2. 事件

    Google 11 月 10 日向开发者、企业和 Ultra 订阅用户开放 Gemini 4 Carbon。官方称它在 CursorBench 4.0、Perplexity WANDR、Zapier AutomationBench 上排第一，单任务成本比第二名低一半以上；日常开发仍推荐 Argon，Carbon 用于复杂多步编码、调试和科研，会消耗更多 token 做验证循环。同时在 Google Antigravity 预览 /swarm：Carbon 负责架构设计、协调和审计，搭配更快的小模型在隔离工作区并行干活，再由对抗式验证者检查每个改动。价格：11 月 30 日前 $2/$10，之后 $4/$20 每百万 token。安全方面称在 Gray Swan 间接提示注入基准上攻击成功率为 0%，agent 诚实性基准通过率 92%（Argon 70%）。

    为什么值得关注

    继 Anthropic 把 Fable 定位成 Advisor/Orchestrator 之后，Google 也把「强模型做规划和审计、弱模型并行执行、独立验证者把关」做成了产品功能，多模型分层 harness 正在成为两家的共识。

    工作中怎么用

    可以在团队的 coding agent 流程里对比 Fable 5.2 和 Carbon 担任规划/审查角色的效果；Carbon 限时价格较低，适合在 11 月底前用真实仓库任务跑一轮对比评测。/swarm 的「隔离工作区 + 对抗验证」结构也可以借鉴到自建 harness。

  3. 事件

    Google DeepMind 11 月 10 日发布 AlphaProof Code，一个多 LLM 的形式化验证 agent 框架。流程是：研究员和模型一起把 Signal 的安全目标翻译成形式化规格（每条都由人工审核），再由 Gemini Carbon 驱动的 agent 写证明，共生成 600 多万行 Lean；agent 再自审证明，只把约 1% 标记给人看。验证对象不是协议设计，而是编译后实际运行的代码，耗时 4 周。为了检验能否区分好坏代码，他们把两个历史上已修复的真实 bug 放回隔离版本，系统都给出了「该版本不安全」的机器可检证明。验证产物会开源。

    为什么值得关注

    这是「规格由人定、执行交给 agent、结果由确定性检查器（Lean）兜底」的典型 harness 设计，把人的精力集中在规格和 1% 的疑点上。它也说明形式化验证的成本正在从「几年」降到「几周」。

    工作中怎么用

    对支付系统的核心不变量（金额守恒、幂等、状态机不可逆转换等），可以试着先写成形式化或可执行规格，再让 agent 生成证明或基于属性的测试，用确定性检查器而不是 LLM 来判定对错。

  4. 事件

    Chrome 团队在 Show HN 发布 Modern Web Guidance 1.0，与 Firefox、MDN、Edge 合作。起因是模型虽然知道 <dialog>、CSS.highlights、field-sizing 等原生能力，却总是默认写成 div + JS 的老模式。项目把 200 多篇（约 1.7MB）专家整理的实现指南做成 agent skill 和 Agentic RAG CLI：作者花 9 个月优化「不撑爆上下文」的分发方式，原本 500MB 的检索栈压到约 7MB 纯 JS 包，本地检索约 10ms；skill 描述专门调优过触发条件。另有基于 3 万个 GitHub 仓库训练的确定性 legacy-scan，找出可现代化的旧代码。用法：npx modern-web-guidance@latest install / search / retrieve / legacy-scan。

    为什么值得关注

    这是「领域知识怎么喂给 agent」的一个认真做法：不是塞长文档，而是按需检索 + 精调 skill 触发描述，作者明确选择不依赖 MCP 动态工具搜索。HN 上也有人担心让所有 LLM 都听 Chrome 团队的建议会加剧浏览器垄断。

    工作中怎么用

    可以照这个结构给团队内部规范做一个 skill：例如 Java/Spring 编码规范、支付接口的幂等和对账约定，做成小体积本地检索 + 精简触发描述，比把规范全文塞进系统提示更省上下文。前端项目可直接安装试用。

  5. 事件

    Evan X. Merz 撰文称，他在 Meta 时 90% 以上代码由 AI 生成是拿到合格绩效的最低要求，现在的公司则要求 100%。他总结 AI 让代码库变脆弱的四个原因：测试只覆盖 getter/setter 和已有路径；过度拆分辅助函数、教条式 DRY；团队对数据结构和算法的理解变浅，看不出新抽象与旧结构不兼容；PR 来得太快，评审只能略读。他观察到的症状是事故逐月增多、定位更慢、只有真实用户才能看到的错误增加。HN 评论中，反对者认为这和带新人一样，是缺少规范、工具和监督的问题，「AI 很擅长遵循好的模式」。

    为什么值得关注

    评论数接近点赞数，说明「AI 产出量 vs 长期可维护性」仍是业界的真实分歧；文中的症状清单（事故频率、MTTR、只有用户能看到的错误）可以直接拿来当度量指标。

    工作中怎么用

    在团队推进 coding agent 时，把事故数、MTTR、测试的变异得分（而非行覆盖率）作为跟踪指标；对支付这类高可用系统，可以在评审规则中要求 agent 写的测试覆盖异常和边界路径，并限制单个 PR 规模。

  6. 事件

    VulnCheck 的 Patrick Garrity 发布 Anthropic Project Glasswing 七个月追踪报告：可归属于 Anthropic 的 CVE 共 442 个，约占今年 CVE 的 0.5%，其中只有 2 个被在野利用。Anthropic 账本截至 11 月 2 日共 37,966 条发现，公开 7,349 条，标记已修复 217 条；9 月以来新增近 12,000 条却只多修了 15 个，重复项从 2 条涨到约 1,670 条，撤回 419 条，而官方宣称的真阳性率反而从 90.8% 升到 94.2%。Anthropic 10 月推出的 OSS Scanner 报告「完全由模型生成、未经人工审核」，curl 收到 45 份，已公开的 34 份里 19 份不是漏洞、6 份确认低危、9 份待评估。

    为什么值得关注

    AI 找漏洞的瓶颈已从「发现」转到「验证和修复」，而且验证成本被转嫁给了维护者。这对任何用 agent 做大规模扫描的团队都是提醒：发现数量不是有效指标。

    工作中怎么用

    如果团队要用 AI 做代码安全扫描，考核指标应是「确认数 / 修复数 / 误报率」而不是发现数，并在报告进入人工队列前加一层去重和可复现性验证（例如必须附可运行的 PoC）。

  7. 事件

    Notion 发布公告：其 AI 推理供应商 Fireworks AI 发生安全事件。Notion 本月早些时候得知后已切断连接，11 月 3 日删除了 Fireworks 上的全部数据并停止训练任务；11 月 6 日 Fireworks 通知可能有客户数据被访问，11 月 8 日确认新数据集。泄露内容是用于 Insights 功能（帮客户分析 AI 使用情况的分类任务）的 Notion AI 聊天记录，不含用户或工作区标识，也不含工具调用结果，影响不到 1% 的工作区。Notion 建议把这些数据视为已泄露，在 Notion AI 里粘贴过密码或 API key 的应立即轮换。受影响工作区的所有者可在侧边栏「?」→「Security incident review」下载受影响数据。

    为什么值得关注

    这是「第三方推理供应商」成为 AI 产品数据泄露点的又一实例。去标识化让影响变小，但用户粘贴进对话的密钥依然暴露。

    工作中怎么用

    盘点团队 AI 功能用到的所有推理和分类供应商（包括做内部分析、评测、训练的），确认数据保留和删除策略；在 agent 输入侧加密钥/卡号脱敏，支付场景尤其要保证 PAN 等敏感数据不进入任何第三方模型调用。

  8. 事件

    稳定币发卡公司 Rain 11 月 10 日发布 Agent Vaults：嵌入式的 agent 支付基础设施，支持通过 ACH、Fedwire、FedNow、SEPA、FPS、银行卡或稳定币充值，资金以稳定币存放在非托管钱包里。每次购买由 Rain 签发一张限定金额、商户和有效期的 scoped 卡，授权时校验，用后作废；还支持向 80 多个国家的银行账户付款、向人或其他 agent 转稳定币、API 调用微支付。卡会携带 Visa Intelligent Commerce / Mastercard Agent Pay 的 agent 凭证来表明用户同意。核心设计是 agent 不能放宽自己的约束，超规则交易即使余额足够也要所有者批准（示例：$5,000 账户，只允许付供应商，超过 $1,500 需审批）。未公布价格和正式上线时间。同日 Visa 稳定币结算计划新增 Monad 链。

    为什么值得关注

    这是 agent 支付「预充值 + 一次性卡 + 规则引擎 + 人工审批」的完整产品形态，正好把卡组织的 agent 凭证和稳定币结算串在一起。

    工作中怎么用

    设计 agent 支付能力时可以参考它的控制模型：资金先隔离、每笔一卡、规则在授权侧强制执行、超限挂起审批。对现有支付系统，可以评估是否需要支持 Visa Intelligent Commerce / Mastercard Agent Pay 的 agent 凭证字段，以及在风控里区分 agent 发起的交易。

  9. 事件

    Anthropic 11 月 10 日发布 Claude Whiteboards（团队白板，Claude 可整理成时间线和行动项）和 Claude Sheets（带公式、格式、下拉的表格，逐格标注修改），均为 beta、所有付费套餐可用。10 月上线的 Claude Dashboards 正式可用并改名 Claude Data，新增：数据团队「认证」的查询和指标口径（图表带认证标记）、实时共享（查看者看到最新数字，但不能用分享者的权限跑其他查询）、缓存与按看板设置刷新频率、版本追踪与回滚。另外，交互式连接器现在可以在对话旁或全屏作为完整应用打开（Adobe、Atlassian、Box、Notion 等）。企业版中 Claude Data 将于 11 月 19 日默认开启。

    为什么值得关注

    「认证查询」本质上是给 agent 一个受控的语义层，避免每次临时生成 SQL 导致口径不一，和 Ontology / 语义层思路一致；交互式连接器则说明 MCP 应用正在从「工具调用」走向「嵌入式 UI」。

    工作中怎么用

    如果公司是 Claude 企业版，注意 11 月 19 日 Claude Data 默认开启，提前确认数仓连接器权限；支付业务的核心指标（成功率、拒付率、对账差异）可以先固化为认证查询，再开放给 agent 自助分析。
