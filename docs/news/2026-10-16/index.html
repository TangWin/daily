  1. 事件

    Meta 发布并开源 Muse Spark Open：总参数 816B，每次激活 42B，支持多模态和 1M 上下文，重点优化写代码和长时间运行的 agent 任务。权重已上架 Hugging Face，两台 M5 Ultra Mac Studio 用 MLX 就能跑起来。

    为什么值得关注

    这是目前少有的、能在本地硬件上跑的前沿级 coding 模型，私有化部署 coding agent 的门槛又降了一截。

    工作中怎么用

    可以评估它作为本地 coding agent 的底座。算成本时别只看参数量，要把显存/内存、上下文长度带来的开销和实际吞吐一起算。

    Meta 博客 ↗HN 讨论 ↗Hugging Face ↗

  2. 事件

    GitLab 官方 MCP Server 随 19.5 正式发布，所有版本、所有部署方式都能用。工具做了合并（如 get_merge_request、get_pipeline），新增代码和流水线相关工具，还能直接启动 Duo Agent 工作流。权限沿用 GitLab 自身的角色体系。

    为什么值得关注

    不用再自己维护第三方 GitLab MCP，权限也和现有角色一致，安全审核更好过。

    工作中怎么用

    用 GitLab 的团队可以把 Claude Code / Codex / Copilot 接到官方 MCP，只开需要的工具组，按最小权限配置。

    GitLab 博客 ↗19.5 发布说明 ↗

  3. 事件

    Stack Overflow 博客文章认为，MCP 已经统一了工具协议，但生产环境需要的配套还缺：认证、网关、可观测性、按需发现工具、最小权限。文中提到按需加载仓库上下文可以砍掉约 87% 的上下文。

    为什么值得关注

    多数团队接 MCP 卡的不是协议，而是这些周边能力；按需发现工具也直接影响上下文成本。

    工作中怎么用

    由平台侧统一做 MCP 网关，集中处理鉴权和监控，别让每个团队各接各的。

    Stack Overflow 博客 ↗

  4. 事件

    Codex CLI 0.163.0 发布：模型回复到一半时可以插话改方向；只读工具并行执行；/config 支持搜索；新增 /daemon 用来重启后台进程。

    为什么值得关注

    中途纠偏和并行只读工具都能明显减少等待时间。

    工作中怎么用

    发现 agent 走偏时直接插话纠正，不必等它跑完再重来。

  5. 事件

    Copilot CLI 1.0.99：新增 --trust-folder，只对本次会话信任某目录；插件可以通过链接安装；新增会话级 /sandbox。

    为什么值得关注

    信任和沙箱粒度更细，临时处理陌生仓库更安全。

    工作中怎么用

    打开不熟悉的仓库时用 --trust-folder 加 /sandbox，不要永久信任。

    Releases ↗

  6. 事件

    Claude Code 2.1.301：无人值守模式下重试时，如果撞上用量上限且距离重置还很久，会直接退出，不再一直等待。阈值可用 CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS 配置。

    为什么值得关注

    CI 或定时任务里跑 Claude Code 时，不会因为额度问题卡住几个小时占着资源。

    工作中怎么用

    在 CI 里设置这个变量，让任务快速失败并报警，而不是悄悄挂起。

    Release ↗

  7. 事件

    GNOME 开发者让 coding agent 对比厂商驱动和自研驱动产生的 USB 通信记录，逐步找出差异来逆向硬件行为，并把这套工具开源为 hw-harness。

    为什么值得关注

    “双边抓记录、自动对比”给了 agent 一个明确可验证的目标，这是 harness 设计的好例子。

    工作中怎么用

    对于行为有标准但没文档的系统（比如支付网关沙箱），可以同样抓参考实现和自己实现的记录做对比，作为验收标准。

    GNOME 博客 ↗hw-harness ↗

    为什么值得关注

    工作中怎么用
