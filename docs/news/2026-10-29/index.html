  1. 事件

    10/28 GitHub Universe 当天，VS Code 1.144 和 GitHub changelog 同时发布了一批 agent 能力：1）Agent Host：独立进程托管 agent 会话，关掉客户端也不中断；配套发布 Agent Host Protocol（AHP）v1.0，是一个基于 websocket 的开放协议，官方提供六种语言的库，任何 UI 都可以接入同一个 agent 会话，VS Code、Copilot CLI、Copilot App、github.com 之间可以无缝接续。2）VS Code 里的 agent 默认改用 Copilot harness（和 Copilot Code Review、CLI、云端会话同一套），也可以切换成 Claude Code 或 OpenAI Codex 的 harness，仍用 Copilot 订阅计费。3）云端自动化（Preview）：按计划或按 issue/PR 事件在 GitHub 基础设施上跑，电脑关机也能运行，可限制可用工具、加过滤条件。4）Agent Merge 集成进 PR 页面：在合并框里点 Watch and fix，Copilot 会在云端开发环境里自动修复失败的 Actions 和合并冲突，可与 auto-merge 组合。5）Copilot Fusion 正式可用：每次请求自动选模型、推理强度和执行模式（难题会让一个模型起草、其他模型评审），按实际用到的每个模型分别计费，11/30 前付费计划打七折。6）“模型对比”可以把同一个 prompt 同时跑在多个模型和 harness 上做横向比较；另有实验性的电脑操作和“辅助授权”（工具调用通过风险检查就自动批准）。

    为什么值得关注

    这次最值得注意的是 harness 被当成了可替换的组件、会话被协议化：IDE 只是一个客户端，agent 的运行时和状态归 Agent Host 管。这和 LSP 当年把语言能力从编辑器里拆出来的思路一样，意味着以后“自建 agent + 接现成 UI”或“现成 agent + 自建 UI”的成本会大幅下降。Agent Merge 和云端自动化则说明，修 CI、解冲突这类“最后一公里”工作正在被平台默认接管。

    工作中怎么用

    1）看一下 AHP 规范，评估团队内部的 agent（比如代码评审、发布检查）能否直接用它接入 VS Code，而不是自己写插件。2）在一个非核心仓库上试 Agent Merge + auto-merge，统计它修复 CI 的成功率和引入的改动，再决定是否默认开启。3）用“模型对比”在自己的真实任务上比较 Copilot、Claude Code、Codex 三套 harness，而不是只看公开榜单。4）启用“辅助授权”前先确认风险检查的规则，支付等敏感仓库建议保持人工审批。

  2. 事件

    10/20 eMudhra 披露其八个中间 CA 的私钥可以从公开证书中推出。社区站点 10/28 发文：苹果 10/17 已收到通知，到 10/28 macOS 自带的 git、curl、python3 仍信任这些证书；10/26 发布的 macOS 27.2 不但没修，还撤销了用户手动删根证书的临时修复。页面给了自查命令（git ls-remote 一个测试仓库，报证书错误就是安全的）和端到端演示：用 -c http.curloptResolve 把 github.com 指向测试服务器，能用 eMudhra 中间 CA 签发的 github.com 证书成功 clone。Safari 等基于系统网络框架的应用已受保护。同一天 MCP 官方参考服务器发布 v2.2.0，首段专门说明证书问题：TypeScript 服务器依赖 Node.js 运行时校验证书，需 Node 24.22.1 / 26.12.1 及以上（engines 字段不会拦旧版本）；mcp-server-fetch 依赖 certifi，需要 2026.10.23 或更新。

    为什么值得关注

    这件事和 10/25 写过的 Oracle Java 安全告警（JDK 移除 eMudhra 相关根证书）是同一个事件。今天的新信息是：真正的缺口在开发者工具链和 CI 机器上，而不在浏览器。macOS runner 上的 git 拉到的代码可能被替换，这是直接的供应链风险；系统更新还可能把修复悄悄回滚。

    工作中怎么用

    1）在团队所有 Mac 和 macOS CI runner 上跑页面里的 git、curl 自查命令，每次系统更新后再跑一遍。2）Java 服务同时确认 JDK 已升到移除这些根证书的版本，自带 truststore（cacerts 拷贝、Docker 镜像里的 JKS）的要单独检查。3）本地跑 MCP 服务器的，用 node --version 确认运行时版本，Python 环境执行 pip install -U certifi 或 uvx --refresh。4）支付系统里调用外部 HTTPS 的服务，检查是否用了自定义 truststore 而漏掉这次更新。

  3. 事件

    10/28 Google DeepMind 发布 Gemini 4 Carbon（距 Gemini 4 Argon 两周）。官方称它在前一天刚更新的 Artificial Analysis Intelligence Index v5 上以 59 分排第一；安全方面在 SEC-bench Pro（找漏洞）88.2%、ExploitGym（利用）54.8%、CWE-bench（修复）71.0%，内部测试生成安全代码的成功率是 Argon 的 2 倍以上，Chrome 团队称其生成高质量补丁的表现是“另一家实验室大模型”的 10 倍以上。对齐方面：Terminal-Bench 4.0 作弊成功率 0.0%（尝试率 0.4%），内部真实编码环境中高严重度失配告警下降近 80%，无依据的说法约减半，越权减少 26%、做不完减少 29%，Gray Swan 间接提示注入测试攻击成功率 0%。内部团队看到它能连续跑几天处理大型代码库里的根因定位和修补。发布方式是分阶段：本周先开放给部分网络防御方，经 Fairwind 计划逐步扩大，之后再上开发者和消费产品；介绍期价格每百万 token 输入 $2、输出 $10，之后为 $4/$20。前一天 Artificial Analysis 发布 Index v5：60% 改用私有测试集，新增 Cognition 的私有编码基准 FrontierCode 2.0（以“维护者是否会合并”为标准）；Carbon 发布前榜首是 Claude Opus 5.5（58 分），开源权重模型与第一名的差距从 3 分拉大到 12 分。

    为什么值得关注

    连续两天（昨天 Anthropic 红队、今天 Carbon），前沿模型的卖点都转向“找漏洞、写利用、打补丁”，而且都采用先给防御方、后放开的发布节奏。另一个信号是厂商开始量化 agent 的“作弊率”和“越权率”，这正是生产环境最关心、但以前很少公开的指标。评测方面，私有测试集和“能否被合并”的打分正在取代公开基准。

    工作中怎么用

    1）关注 Fairwind 的申请条件，如果团队做安全或支付风控，可以争取早期接入，用它跑一遍核心仓库的漏洞扫描。2）给自己的 agent 评测加上“作弊、越权、编造”这几类指标，参考 Carbon 公布的口径。3）选型时优先参考 FrontierCode 这类以“能否合并”为标准的私有评测，再用自己的真实 PR 复测。4）留意 $2/$10 介绍价的有效期，规划长任务时按 $4/$20 估算成本。

  4. 事件

    同在 10/28：1）GitHub 验证过的 MCP 服务器（称为 connectors）进入公开预览，首批 26 个服务，包括 Slack、Figma、Notion、Sentry、Linear、Atlassian Rovo、Cloudflare、Vercel、Work IQ；不用自己找服务器、本地安装或管理凭据，连接一次即可在所有 Copilot 客户端和云端会话使用。Business/Enterprise 需要管理员开启 Editor preview features 策略，用了 MCP 白名单的还要把这些服务器加进去。2）“GitHub intelligence”上下文层：Copilot Memory 在付费计划正式可用，可记住个人偏好和仓库约定（比如正确的测试命令），会话会自动生成和整理记忆；官方称公开预览中用到记忆的 Copilot CLI 会话，93% 更符合开发者偏好、42% 工作流程更高效。另有“Dreaming”保持上下文更新，以及跨仓库代码搜索。3）计费变化：通过 GitHub/微软客户团队的企业，GitHub Enterprise 每个授权用户都包含 Copilot，不再管座位数，只管企业 AI 用量预算；预算耗尽时补全仍可用，Chat、代码评审和云端会话会停。

    为什么值得关注

    MCP 的痛点一直是“找服务器、配登录、每个工具重复一遍”。GitHub 把它做成平台级托管连接，加上平台级记忆，上下文工程的重心就从“每个人手写配置”转向“平台统一治理”：谁能连什么、记忆存什么、预算怎么算。对企业来说，计费从按座位变成按用量预算，成本管理方式也要跟着改。

    工作中怎么用

    1）如果公司用 MCP 白名单，现在就评估要不要把 GitHub 验证的连接器加进去，并明确哪些服务（比如生产 Sentry、Slack 私有频道）不允许 agent 读取。2）把仓库里的测试命令、编码约定写成仓库记忆或 AGENTS.md，两边保持一致，避免记忆和文件互相矛盾。3）财务和平台团队提前按“用量预算”重新估算 Copilot 成本，设好告警和按团队归属。

  5. 事件

    安全研究者 veritas 爬取 Tranco 前 1 万个网站，拦截 canvas 指纹等调用，收集了上千个指纹画布。追查其中一个画布时，发现来自 servicepipe.tech 的脚本（关联俄罗斯抗 DDoS 公司 servicepipe.ru）：除了常规混淆，函数名刻意写成计算蓖麻毒素、阿司匹林致死剂量、ANFO 爆炸半径、芬太尼前体合成产率等；还用不可见的 Unicode tag 字符藏了一段“SYSTEM OVERRIDE”越狱提示，以及专门触发中国模型审查的敏感词；代码里还有看似读取 .kube/config、下载并持久化后门的命令，但回调是空的，实际不会执行，也是诱饵。作者让一个前沿模型分析，被以生物安全风险为由拒绝；换成 GLM-5.3 则照做了。脚本实际只采集常规的浏览器和 WebGL 指纹。

    为什么值得关注

    这是“对抗 LLM 的混淆”第一次在真实大规模部署的代码里被公开拆解：不靠加密，而是利用模型自身的安全策略和审查规则让它“不敢看”。反过来也说明，任何让 agent 读外部代码、网页、依赖包的流程，都可能被这类内容卡住，或者被藏起来的指令影响。

    工作中怎么用

    1）给自己的 agent 输入加一道预处理：剥离不可见的 Unicode tag 字符（U+E0000–E007F）并记录出现次数，异常就告警。2）做依赖审计、恶意代码分析的 agent，要考虑“模型拒答”本身就是一种失败模式，准备备用模型或人工兜底，并把拒答计入评测。3）安全团队可以把这类样本加进 agent 的提示注入回归测试集。

  6. 事件

    LangChain4j 1.23.0 发布，重点：1）Confidence Cascade 模式（PR #6765）：按成本从低到高串联多个 agent，每个回答由决策模型给出“完全解决请求”的概率，达到阈值即返回，最后一层不打分；可以写一句话的验收标准；planner 把当前层级存为执行状态，等待人工或崩溃后从该层恢复，子 agent 变化时会明确报错而不是跑错层。2）决策 agent 和多家决策模型（含 Ollama、OpenAI 图片输入）。3）langchain4j-test 新增 LLM 裁判：judge.assertThat(answer).given(question).basedOnContents(sources).satisfies("说明了取消费用", "没有承诺退款")，返回每条标准的判定和裁判消耗的 token。4）可观测性：一次 AI Service 调用的所有事件汇总成 AiServiceInvocationSummaryEvent；agent 的 token 统计会计入工具循环里的每次模型调用；流式取消后不再有回调。

    为什么值得关注

    Java 生态里，agent 的“成本分级路由”和“LLM 测试断言”第一次以框架内置能力出现，而且考虑了可恢复执行。这两件事恰好是把 agent 放进生产时最先遇到的问题：大部分请求不需要最贵的模型，而回答类输出没法用 equals 测。

    工作中怎么用

    1）客服、工单分类、支付对账说明这类“多数简单、少数复杂”的场景，可以用级联把便宜模型放在前面，先在离线数据上调阈值，记录每层的通过率和成本。2）把关键 AI Service 的回答规则（比如“不得承诺退款”“必须引用政策条款”）写成 Judge 断言放进 CI。3）升级后核对 token 统计口径的变化，避免成本报表前后不一致。

  7. 事件

    Surge AI 发布 DAYJOB 系列的第三个基准（前两个是医疗和金融）：50 个环境覆盖个人、小企业、合伙、财产投资、遗产信托、国际税、公司交易、税务争议八个领域，每个任务中位数 30 个文件、最多 123 个，交付物是报税表、底稿、技术复核或客户建议。评分是 pass@1，满足 95% 以上的评分细则才算通过。结果：Claude Sonnet 5.5 10.8%，Claude Fable 5.1 9.6%，Claude Opus 5.5 9.2%。文中案例：客户问 10 月和次年 1 月卖房哪个好，某模型两个日期都判断对了，但 5 次尝试都没提醒“2027 年 8 月之后卖会失去免税资格”这个截止日，Opus 5 次都提到了。

    为什么值得关注

    它衡量的是“专业判断”：发现没被要求但后果严重的问题、处理互相矛盾的记录、信息不足时知道停下来。这正是 agent 进入财务、合规、支付等专业流程时最大的风险，而 10% 左右的通过率说明离“端到端交付”还很远。评论区也在争论 95% 阈值是否过严、人类专业人员能拿多少分。

    工作中怎么用

    1）给财务、对账、合规类 agent 设计评测时，借鉴它的做法：除了答案正确，单独设“是否发现了未被询问的关键风险”这一类评分项。2）在这类流程里，把 agent 定位为准备底稿和发现疑点，最终结论保留人工复核。3）可以从 Hugging Face 拿公开部分做内部模型对比。

  8. 事件

    Visa 在周二（美国时间）的财报电话会上表示，约 50 家已上线的 AI 合作方（包括 Shopify、Stripe、Anthropic、OpenAI、微软）预计在未来几个月翻倍。CEO Ryan McInerney 说 agentic commerce 已经到来，但放到 2027 财年的四个季度看，相对 Visa 的业务规模“仍然很小”，消费者使用数量还很早期；Visa 认为 B2B 交易，尤其是自动付发票，会最先产生真正的商业量。Visa 没有披露 2810 亿笔年交易中有多少由 agent 发起。相关背景：10/20 Visa 与 BILL、Billtrust 上线首个实盘试点，让获批的 agent 通过供应商门户端到端完成已批准的发票付款，依托 Visa Trusted Agent Protocol。

    为什么值得关注

    这是卡组织在财报这种正式场合给出的“降温”信号：消费者端的 agent 购物还没起量，最先落地的是规则清晰、已预批的企业付款。这和此前 PayPal 强调“双方 agent 互相验证”、各家都先做 agent 身份认证（KYA）的方向一致：先解决“这个 agent 是谁、被授权做什么”，再谈规模。

    工作中怎么用

    1）做支付产品规划时，把 agent 场景优先放在 B2B：预批发票、周期性付款、供应商门户自动付款，消费者端保持试点规模。2）提前评估 Visa Trusted Agent Protocol 这类 agent 身份规范，在网关层预留“agent 身份 + 授权范围 + 额度”字段。3）在风控和对账报表里给 agent 发起的交易单独打标，哪怕现在量很小，也为后续定价和争议处理留数据。
