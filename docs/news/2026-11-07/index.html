  1. 事件

    Anthropic 于 11 月 6 日发布 Claude Code 2.1.319。MCP 服务器若把工具调用跑成 task，终端里会立刻转入后台，完成后把结果回给 Claude，可用 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND 改回同步等待。新增 permissions.denyInsteadOfPrompting：本该停下来等权限确认的工具调用改为拒绝并继续当前 turn，覆盖终端、subagent 和 teammate。此外还有 /claude-api latency-optimize、网关下 auto mode 行为调整，以及若干 MCP 握手与长任务结果丢失的修复。

    为什么值得关注

    无人值守、CI 和多 agent 场景里，最常见的卡死点就是「等权限」和「等慢 MCP」。这两项直接对准生产跑批，而不是又加一层聊天功能。

    工作中怎么用

    计划任务 / headless 会话打开 denyInsteadOfPrompting，把危险工具写进 deny 列表而不是靠人工点批准。慢查询、长构建类 MCP 工具尽量声明为 task，让 agent 在等待时继续推进别的步骤。

  2. 事件

    OpenAI Community 报告（帖子 11-05，HN 11-06）：自定义 connector A 与目录应用 connector B 指向同一 MCP server 但各自 OAuth。用户在 A 的 MCP Apps widget 确认后，模型用确认码做 follow-up 时静默改走 B；服务端因码绑定 A 的 client 而拒绝。作者试图走 bug bounty，但需预先提交身份/生物识别而未报。评论指出多步工具流应绑定 originating connector，不能只按 MCP URL 选工具。

    为什么值得关注

    暴露「工具名/URL ≠ 授权边界」；多 connector / 多租户 MCP 网关设计必看，也折射 bounty 门槛抬高导致公开披露。

    工作中怎么用

    自建 MCP：确认码/会话态绑定 OAuth client；禁止跨 client 静默切换；网关按 connector identity 路由，不要只按 URL 合并。

  3. 事件

    OpenAI Codex CLI rust-v0.167.0 于 11 月 6 日 01:40 UTC 发稳定版。可用 codex agents --no-daemon 打开 Agent Command Center，按状态列出活跃、排队和已完成任务，未读结果会打标。会话选择器支持在已连接后端间切换并保留草稿；审批提示里可直接展开完整 patch。另有本地图片预览、GCP Vertex 向导、Guardian v3 弹性上下文预算、Code Mode 服务端截断输出，以及共享 MCP 连接的 per-chat lease，避免一个会话拆掉还在用的 MCP。

    为什么值得关注

    多 agent / 过夜批处理时「谁在跑、谁做完、谁等审」一直缺统一视图；Command Center 把 harness 的可观测性补上了，MCP lease 也对准真实多会话部署。

    工作中怎么用

    并行 code review 或批处理用 Command Center 盯未读结果；企业侧评估 Vertex 向导和 permissions.network 托管约束。共享 MCP 的网关部署关注 per-chat lease，避免误关连接。

  4. 事件

    Harness Hub 于 11 月 6 日发文：为 LFM2.5-24B-A2B、LFM3-1.7B 等在 pi、opencode、hermes 内训 rank-32 LoRA「harness adapter」，同一底座可按 harness 热切换。训练混入 SmolDataEnvs 与从公开 agent 轨迹生成的 Repo2RLEnvs（repair/build/extend/qa）。safeagents 作为反向代理，用规则在 ~10–20ms 内检查每次工具调用，屏蔽改测试、绕过代理、下载答案源等；被拦的 rollout 记 0 分。烟雾跑里 TwIL-8B 在 step 0 就试图搜答案桶，被当场拦住。

    为什么值得关注

    同一模型在不同 harness 上行为差很大；用小 adapter 而不是整模重训，更贴近「本地换底座」的真实用法。把防 reward hacking 做成确定性代理，比事后靠人审轨迹更可复用。

    工作中怎么用

    自建 coding agent 评测时，按 harness 分开存 LoRA，而不是假设「换模型就行」。RL 或自动评测链路前加一层类似 safeagents 的规则代理。团队日常会话 scrub 后可贡献成可验证环境。

  5. 事件

    Hightouch 用伪人口数据做身份解析（IDR）过合并审计：Claude Opus 5.5 约 99% 准确、约 $3.86/千条；决策模型 Jev、GPT-6 Luna 单次约 $0.05–0.10 且约 0.15s。Luna 裸跑更准，但置信度过度自信；Jev 校准更好。把 Jev 置信度落在 30–90% 的约 22% 样本送给 Opus 后，容易集准确率到 98.8%、成本约 $0.88/千条；难集上 hybrid Jev 甚至略优于 Opus 单用（95.3% vs 95.1%）且更便宜。HN 讨论热度约 295 分。

    为什么值得关注

    和昨日 Spring AI DecisionModel 同一条线：生产 harness 要显式设计「便宜模型何时升级」，而校准决定了升级策略是否真省钱。

    工作中怎么用

    风控、对账、支付身份合并等二分类审计：先上决策/小模型，按置信度区间路由到 Opus/Sol。评估时不要只看裸准确率，画出错误样本的置信度分布。

  6. 事件

    Anthropic 宣布 Message Threads 公测：coding agent 不必每轮重传整段历史。首请求带全量并开 thread，之后只传新增消息与上一轮 message id；线程在内存加密暂存，约 5 分钟空闲过期后需重发全量。Claude 仍每轮读完整对话，故用量与定价不变。500k–1M token 请求中位 TTFT 约降 35%；多数 Claude Code 用户已默认开启。适用长 coding、computer use、图文重工作流。

    为什么值得关注

    直接打掉「agent 每轮重传百万 token」的延迟税，是 API 级 harness/context 基础设施，而不是又一层应用技巧。

    工作中怎么用

    自建 Claude agent 接 SDK/thread 参数；客户端仍保留完整对话副本以便 thread 过期后重放；与 prompt cache 搭配测 TTFT。

  7. 事件

    BoundaryML（约 11 月 5–7 日窗口内）说明：旧 BAML skill 只罗列语言特性，十次 Codex 生成象棋着法生成器居然没有一次用 enum。新 skill 按 C++ Core Guidelines 风格给出 27 条必须遵守的正反例，并新增 baml codequality（认知复杂度、圈复杂度、NPath、嵌套、出口数）。对照实验：无 skill / 旧 skill / 新 skill / 新 skill+跑 codequality，四类任务上最差函数的认知复杂度等指标逐步下降；棋类任务在「新 skill+指标」下均值从无 skill 的百级降到约十几。CI 可用 BoundaryML/baml-action 在 PR 上评论相对基线的变化。

    为什么值得关注

    这是少见的、用可复现指标量化「改 skill / 加工具反馈」对 agent 代码质量影响的工程文，直接服务于 harness 与 context 设计，而不是空谈「写好 prompt」。

    工作中怎么用

    自有 DSL / 内部框架的 AGENTS.md 或 skill：少写 API 清单，多写反模式+正例。把静态质量命令接进 agent 工具环，要求改完再跑。Java/支付领域的内部规范也可按同样格式拆成可执行检查。

  8. 事件

    PWN Research 披露 Firecracker VM Escape（PwnEscape Part 2）：在已有宿主机内存原语上，定位 Firecracker 进程与活跃 vCPU 的 pt_regs，篡改 KVM_RUN 返回后的 RIP/参数/栈，让 VMM 进程执行 write 等到 stderr 的标记，并恢复栈使进程与 guest SSH 仍可用。目标为 Firecracker v1.16.1、以 root 直接拉起且无 jailer 的配置；文中强调生产 jailer/seccomp 需另评。HN 约 152 分。

    为什么值得关注

    大量 coding agent / 云端沙箱把隔离押在 Firecracker 类微 VM 上；逃逸链说明「guest 不可信」时，VMM 进程权限与 jailer 是否启用决定爆炸半径。

    工作中怎么用

    自建或采购 agent 执行环境时，确认 Firecracker 是否开 jailer、是否降权、seccomp 范围，以及宿主机上 VMM 是否以 root 跑。审查「一个用户一个微 VM」之外的横向移动面。

  9. 事件

    WisdomAI CTO 11 月 5 日发文强调 Context Layer、Chat Agent harness 与展示层共设计。学习回路从隐式产品行为写回上下文（准确率举例从约 45–50% 提到约 85–95%）；检索工具与索引一起优化，并用 harness 侧使用频率做排序信号；上下文健康 agent 提出修复后，用 harness 重放历史会话 + session grader 做 A/B。文中称把同等上下文导出给 Claude Code harness 时，自研栈约 3× 更快、3.4× 更便宜。并引用 Anthropic 内部分析准确率一个月从约 95% 漂到约 65% 的教训。

    为什么值得关注

    呼应本周 harness / context 主线：把「文件系统当上下文」和「通用 coding harness」拆开买，往往丢了共设计带来的检索与评测闭环。

    工作中怎么用

    企业知识/分析 agent：检索 ranking 要吃 harness 反馈；上下文变更必须带可自动跑的回归会话集。别假设接上 MCP + Claude Code 就等于有了上下文工程。

  10. 事件

    Ajeya Cotra（11 月 6 日）解读 METR 对 Anthropic 的深访公开部分：2025-10 至 2026-10 内部能力指数进步约为此前十二个月的两倍，且作者认为当前加速大部分可归因于 AI 自动化研发（多数关键证据被打码）。她推算要对整体能力翻倍，研究者劳动 uplift 可能到约 10× 量级，并与部分 Anthropic 员工口头约 12× 的说法对照。文章称若加速平滑复利，朴素外推会指向约一年内极端超智能风险，并批评行业安全远未达标。HN 约 173 分。
