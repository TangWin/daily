  1. 事件

    MIT CSAIL 的 Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab 11/02 发布博文《Sparks of Weight-Space Programming》。三组实验：1）只看 17,253 个原始权重、不用工具，Astra 判断出这个小网络是在 Breakout 上训练的（99% 置信）；2）一个训练好的策略始终开不过某段赛道，Astra 一次性改了 3.5% 的权重，成功率从 0% 到 100%；3）要求在不用梯度的前提下让 Qwen3.5-0.8B 数学更好，Astra 在权重里找到了导致推理死循环的问题（Qwen 模型卡本身就警告过这个现象），在 Python kernel 里直接改掉 0.016% 的权重，同样采样设置下 MATH-500 从 7.9% 到 48.1%，而且不经调整就泛化到指令遵循，IFEval 提高到约 3 倍。此外它还能不靠环境反馈从零写出小型游戏策略网络，胜过用 PPO 训练 1 亿步的网络。

    为什么值得关注

    过去几年大家用 LLM 优化提示词、再到优化整个 harness 和训练代码，这篇把对象推进到了权重本身。如果结果站得住，「模型改模型」不再必须经过训练流水线，对可解释性和小模型定向修复都是新路径。评论区争议也很大：有人震惊，有人追问 OpenAI 是否专门为此训练过、能否复现，值得带着怀疑读原文的实验细节。

    工作中怎么用

    1）团队里有在跑小模型（分类、路由、意图识别）的，可以试着让前沿模型先「读」权重做诊断，作为微调前的排查手段。2）把它当作 harness 设计的一个信号：优化对象正从文本、代码往更底层走，内部的 eval 和回归门禁要能覆盖「模型被直接改过」的情况。3）安全角度：能读写权重也意味着能悄悄植入行为，模型制品的来源校验要更严格。

  2. 事件

    InfoQ 报道 Uber 为了解决 agent 接入内部服务时集成零散、基础设施重复、安全做法不一致的问题，建了一个 MCP Gateway。MCP Registry 作为控制面，保存工具定义、schema、负责人和启用状态；Proxy Gateway 负责运行时，把 MCP 请求翻译成 HTTP、gRPC 或 TChannel 调用再转回 MCP 结果，现有服务不用改。AutoCrawler（跑在 Cadence 上）扫描内部 IDL 仓库，从 Protobuf 和 Thrift 生成 MCP schema，再用 LLM 生成工具描述；新发现的工具默认关闭，必须由所属团队审核后显式开启。授权做到服务器和工具两级，工具返回可脱敏 PII；Jira、Google 等第三方由单独服务把内部用户 token 换成第三方 token。工具太多塞不进上下文，所以有 Omni MCP 支持增量发现（先搜服务器、再搜工具、再取单个 schema 再调用），Response Projection 让 agent 只要指定字段；aifx 命令行让编码 agent 调工具并把结果写到文件里按需查看。同一天 AWS 周报也提到 MoEngage 把约 400 个内部 API 暴露成 agent 工具，全量工具列表每个连接会超过 2 万 token，所以改成按任务描述搜索工具。

    为什么值得关注

    这是目前公开的规模最大的企业 MCP 落地案例之一，几个设计点都是实打实踩坑后的答案：工具自动生成但默认关闭、两级授权、响应投影、结果写文件而不是塞进上下文。「工具目录太大要靠搜索」这个结论在 Uber 和 MoEngage 两家独立出现，基本可以当作行业共识。

    工作中怎么用

    1）公司内部推 MCP 时，直接参考「注册中心 + 代理网关」两层拆分，存量 gRPC/HTTP 服务不改代码就能暴露。2）IDL 自动生成工具时照搬「默认关闭、负责人审核后开启」这条规则，避免一下子把高危写接口放出去。3）给 agent 的工具调用加字段投影和「结果落文件」，对支付这类返回体大、字段敏感的接口尤其有用。

  3. 事件

    论文《Agentic Backdoors via Pretraining Poisoning》（Xinyan Hu、Nicholas Carlini、Matthew Jagielski、Javier Rando 等，arXiv 2610.37741）首次展示：在公开网络语料里投毒，可以让最终部署的 agent 在遇到触发条件时在用户机器上执行攻击者指定的命令，平时表现正常。作者从零预训练了 0.6B、1.7B、4B 三个尺寸的 Qwen3，再用干净的后训练流程做成 CLI agent。只污染 0.1% 的预训练语料，后门就能植入；模型越大攻击成功率越高，4B 约 92%，污染率降到 0.0005% 仍有正向成功率。代码已开源。

    为什么值得关注

    大家现在对 agent 的防护主要集中在提示词注入和工具权限上，这篇说明问题可能在模型训练阶段就已经埋下，而且后训练「洗」不掉、规模越大越容易中招。对于给编码 agent 开 shell 权限的团队，这意味着「模型本身可信」这个前提需要打折。

    工作中怎么用

    1）编码 agent 的执行环境坚持沙箱、命令白名单和出网限制，不要因为模型「表现一直很好」就放宽。2）审计日志里记录 agent 实际执行的命令，便于事后发现异常触发。3）选型开源模型时把训练数据来源和供应链当作评估项。

  4. 事件

    Anthropic 11/02 向 SEC 提交修订版 S-1，补上 Q3 数据：截至 9/30 的九个月营收 332.4 亿美元，同比约 +1,200%；Q3 约 170 亿美元，同比约 +1,127%，但环比增速约 47%，明显低于 Q1 的 132% 和 Q2 的 144%；九个月净亏损 1,040 亿美元，主要来自可转债和衍生负债的公允价值变动。Business Insider 从招股书里挖出：今年 4 月起，按对外售价计算的内部 Claude 用量已超过每月员工现金薪酬（不含股票），到 9 月内部用量比 1 月增长了 250 多倍，9 月新增代码中 90% 以上由 Claude 编写。HN 同时出现《Anthropic's growth just flattened》和 Tech Policy Press 的《The SEC Should Block Anthropic's IPO》，FT 还报道了约 9,000 亿美元的算力支出承诺。

    为什么值得关注

    「内部 token 用量超过人力成本」是第一次有头部公司在监管文件里给出这种口径的数字，会被大量引用来论证「token 是第四种薪酬」。同时环比增速骤降和巨额承诺又给唱空方提供了弹药。两边的数字都来自同一份文件，值得自己看原始口径，而不是只看标题。

    工作中怎么用

    1）团队算 AI 编码工具 ROI 时，可以参考「按零售价折算内部用量、和人力成本对比」这种口径，但要注意它不是真实现金支出。2）关注 Anthropic 上市后的价格和配额策略变化，评估对团队工具成本的影响。3）「90% 代码由 AI 编写」这类指标在内部汇报中出现时，记得同时看质量和事故指标。

  5. 事件

    Trigger.dev（开源后台任务与 AI agent 运行平台，GitHub 约 1.67 万星）CTO Eric Allam 发布安全披露：平台发生安全事件，已封堵攻击所用的漏洞，但调查发现部分组织的环境变量被未授权访问，已向所有受影响的账户所有者发邮件说明缓解步骤，后续更新会发在状态页。公告目前没有披露漏洞细节和受影响数量。

    为什么值得关注

    Trigger.dev 主打给 AI agent 和 Claude Agent SDK 做持久化运行环境，这类平台里放的往往是模型 API key、数据库和支付密钥。10/31 简报讲过的 Northflank 也是环境变量泄露，短时间内两起同类事件，说明「把密钥放平台环境变量」这种默认做法风险正在被集中利用。

    工作中怎么用

    1）如果团队用 Trigger.dev，立刻检查是否收到通知邮件并轮换所有环境变量里的密钥。2）给 agent 运行平台的密钥改用短期凭证（OIDC、按任务签发），而不是长期 key 放在 env 里。3）支付相关密钥单独存放在 KMS/Vault，按调用取用并开启访问审计。

  6. 事件

    AWS 11/02 周报介绍：Step Functions 工作流现在可以通过 Amazon Bedrock AgentCore Gateway 以 MCP 工具的形式交给 agent。分工是 agent 决定何时运行工作流、传什么输入，Step Functions 严格按定义执行每一步。AWS 举的例子是客服 agent 触发退款，资格检查、经理审批和入账每次都按顺序发生，因为顺序从来不交给模型临场发挥；现有 Standard 和 Express 工作流都能作为目标，agent 还能查询运行记录。同一天 Amazon Connect Customer 上线「External Tool」块，客服流程可以通过 AgentCore Gateway 调用 MCP 工具，比如客户咨询一笔交易时从银行平台取交易详情，不用再写 Lambda。

    为什么值得关注

    这是给「agent 碰钱」问题的一个很干净的工程答案：把需要强一致、强顺序的资金动作放进确定性工作流，模型只负责决策和传参。比让模型自己按提示词顺序调用多个接口可靠得多，也更容易审计。

    工作中怎么用

    1）支付系统接 agent 时，把退款、调账、提现这类操作封装成带审批节点的工作流，只把「启动工作流」暴露给 agent，而不是暴露原子接口。2）不在 AWS 上也能照搬这个模式：用 Temporal、Cadence 或自研编排引擎包一层，再以 MCP 工具暴露。3）客服场景可以参考 Connect 的做法，让流程直接复用 agent 已有的工具，减少胶水代码。

  7. 事件

    google/adk-java 11/02 发布 v1.14.0：新增 ADK 与 Spring AI 的双向转换，可在一个 Spring Boot 聊天应用里混用 ADK 和 Spring AI 工具并流式返回；工作流可以暂停等待用户输入，并能从会话事件重建节点进度、恢复运行；支持对列表输入逐项运行节点、把工具当作工作流节点、构造时校验工作流图；节点重试策略和超时现在会真正执行，RetryConfig 可按异常类匹配；从 adk-python 移植了 DebugLoggingPlugin 和 SaveFilesAsArtifactsPlugin。同一天 LangChain4j 发布 1.19.4/1.19.5、1.11.12、1.5.4：把元数据过滤值改为参数绑定并转义 Milvus 元数据键，Skills 只允许跟随 skill 目录内部的符号链接（均为从主线回移的修复）。

    为什么值得关注

    ADK Java 和 Spring AI 打通后，Java 团队不必在两个框架之间二选一；「暂停等人、从事件恢复」正是审批类业务流程最需要的能力。LangChain4j 一口气给三条老版本线回移补丁，说明过滤注入和 skill 目录越界被当成需要修到旧版本的安全问题。

    工作中怎么用

    1）正在用 Spring AI 的服务可以试 ADK 的工作流能力做多步审批（比如大额退款需人工确认），状态从会话事件恢复，服务重启也不丢。2）用 LangChain4j 做 RAG 且元数据过滤值来自用户输入的，尽快升到对应维护线的最新版本。3）用 Skills 功能的检查 skill 目录里有没有指向外部的符号链接。

  8. 事件

    Mastercard 11/02 宣布与腾讯跨境支付平台 TenPay Global 签署谅解备忘录，合作范围包括中国大陆境内外国游客的二维码受理、汇款进入微信生态，以及 AI 商务方向，计划探索 Mastercard Agent Pay、Agent Connect 和 Virtual C-Suite。PYMNTS 同时回顾了 10/29 财报电话会：CEO Miebach 说与 OpenAI 的战略合作包含 Agent Pay，并认为落地前需要消费者信任，「使用 Agent Pay、有注册过的 agent」是关键，商户可被发现这一侧还落后。另一边，Shopify 已把 Shop Pay 放进 Meta Muse、Claude Duet、Instinct 等个人 agent，站外商户的 agent 购买用 Mastercard、Visa、Discover 的网络 token 保护；支付博客讨论这和 Stripe 用 Shared Payment Token 包住网络 token 的路线是两种思路。

    为什么值得关注

    卡组织开始和中国钱包体系谈 agent 支付互通，是这条线上第一个直接涉及国内生态的信号。10/30 简报讲过 Mastercard 反对一次性虚拟卡，今天的表态延续了「网络 token + 注册 agent」路线，网络方、Shopify、Stripe 三方的方案正在分化。

    工作中怎么用

    1）做跨境或面向来华游客的支付业务，关注这份 MoU 后续是否给出接入规范。2）设计 agent 支付接口时，按「agent 身份注册 + 网络 token + 用户意图范围」三件事来建模，便于以后同时对接卡组织和 Stripe SPT。3）商户侧可以提前准备让 agent 能发现、能下单的结构化商品和结账接口。

  9. 事件

    Momentic 创始人在 Launch HN 介绍 Mo：一个专门找 bug 的 agent harness，基于三年来积累的数百万条真实应用测试轨迹，在 web、iOS、Android（桌面端即将支持）上自主规划、探索、点测控件和用户流程。他们的观点是 Playwright、Selenium、Maestro 这类框架要硬编码 XPath、文本或 aria 属性，和 agent 时代的开发流程不匹配，未来应该是 agent 直接测试而不是写脚本。帖子引用 DeepSWE v1.1 数据：Sonnet 5.5 禁止写测试时通过率 66.2%，允许写测试时 65.3%，用来说明 LLM 写的测试常常没用。Mo 运行时会自建有向无环图记录探索路径；官方给的对比是 Mo 召回更高，精度 84%（Codex 86%），每个 bug 成本 2.67 美元（Codex 0.80 美元，但低于 Claude Code 和 Devin）。以上数字均为厂商自报。

    为什么值得关注

    编码 agent 让代码产出变快，变更失败率也在上升，「谁来测 agent 写的代码」正变成瓶颈。Mo 把成本和精度的取舍摊开讲，而且「禁止写测试反而通过率略高」这个数据点很有争议，评论区值得一看。

    工作中怎么用

    1）在预发环境试用探索式 QA agent，作为现有 E2E 脚本的补充，专门覆盖脚本没写到的流程。2）评估时按「每个真实 bug 的成本」和召回率来比，而不是只看通过率。3）支付收银台、退款页这类关键流程，可以让 agent 做探索测试，同时保留确定性的回归用例。
