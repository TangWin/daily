  1. 痛点

    很多网站为了分析、A/B 测试、客服和广告，直接嵌入第三方公司托管的 JS。脚本由对方随时更新，网站方完全不知道哪天被换了内容。这次 Optimizely 被攻破，CNN、Zoom、GitLab 等网站一行代码没改，却给访客投放了盗信用卡、盗加密货币地址的恶意脚本。评论里的共识是：应当把第三方脚本放到自己服务器、过审后再上线、设冷却期，并用严格的 CSP 限制来源，但大多数团队没人手做。

    目标用户

    中小电商和 SaaS 的前端或运维负责人（尤其有结账、登录页的）；市场部塞了很多跟踪代码的公司网站；接网站维护的代理公司；需要满足 PCI DSS 4.0 支付页脚本管控要求的商家。

    现有方案

    Cloudflare Page Shield、Akamai Page Integrity、Jscrambler、Feroot（企业级客户端脚本监控）；Report URI、CSP Evaluator（CSP 工具）；SRI 哈希（浏览器原生）

    现有方案的缺陷

    企业产品贵、要销售对接，小网站用不起；CSP 和 SRI 要手工写，第三方脚本一更新 SRI 就失效，大家干脆不用；死链和挂马检查只看域名和黑名单，看不出「正规供应商的脚本内容变了」；出了事也说不清这段脚本能拿到页面上哪些数据

    解决方案

    输入网站地址，用无头浏览器按关键页面（首页、登录、结账）跑一遍，列出所有外部脚本及其来源、大小、内容哈希，以及它们读了哪些表单和 Cookie。之后定时复查：脚本内容变了、出现新域名、开始读支付表单字段，就立即报警并给出差异。一键生成 CSP 白名单；可选「代理托管」模式：把第三方脚本拉到自己域名，变更后先隔离 24 小时、人工确认再放行。

    MVP

    网页版加每小时巡检：最多 5 个页面，显示外部脚本清单和哈希，内容变化或新域名出现时发邮件或 Slack；生成可直接粘贴的 CSP 头；结账页单独标红。免费扫一次，按站点收月费。

  2. 痛点

    macOS 上很多 App 一安装就要求「完全磁盘访问」，这意味着能读你的邮件、聊天记录、照片库和代码仓库里的密钥。HN 上有人数出自己 Mac 上 44 个 App 要过这个权限，只给了 8 个，其余照样能用；计算器、背单词软件也要。系统设置里的权限页面混乱，常常看不出到底给没给；普通用户根本不懂每个弹窗意味着什么。

    目标用户

    注重隐私的 Mac 用户和开发者（电脑里有代码和密钥的）；给员工管电脑的小公司 IT；家里人用 Mac 的「家庭技术员」。

    现有方案

    macOS 系统设置「隐私与安全性」；Objective-See 的 KnockKnock、BlockBlock（查启动项和持久化）；Little Snitch（网络层）；企业 MDM（Jamf、Kandji）

    现有方案的缺陷

    系统设置只能逐项点开看，没有一张总表，也不告诉你「这个 App 不给也能用」；Objective-See 工具偏安全研究者，不管 TCC 权限是否必要；MDM 面向企业、个人用不上；没有大家共享的「哪些 App 拒绝后照常工作」经验库

    解决方案

    Mac 小工具：读取本机 TCC 权限记录（完全磁盘访问、文件夹、屏幕录制、辅助功能、麦克风等），生成一张总表，按风险排序。对每个 App 显示众包结论：「拒绝后功能正常 / 只影响某个功能 / 必须要」，以及它为什么要。提供一键跳转收回；定期提醒新增的高危权限；标出权限范围内有哪些敏感目录（含 .env、SSH 密钥、聊天数据库）。

    MVP

    免费菜单栏 App：权限总表加风险评分、跳转到对应系统设置收回；内置前 300 个常见 App 的「需不需要」说明（先人工整理，再收用户反馈）；新增完全磁盘访问时通知。付费版：多台 Mac 汇总报告给小公司 IT。

  3. 痛点

    独立开发者为了获客往往一下午提交 50 到 100 个产品目录站，每个页面都定格在提交那天的价格、标语和截图。之后涨价、取消免费版、改名或换域名，旧信息还挂在几十个想不起来的页面上。反过来，你写的教程依赖别人的产品（比如 Google NotebookLM），对方一更新功能，你网站上五处说法就错了。还有数据源突然不让引用，要找出所有引用过它的文章。

    目标用户

    做 SEO 和目录站推广的独立开发者和小 SaaS；写对比、教程内容做获客的内容团队；做联盟营销和测评网站的站长。

    现有方案

    Google Alerts、Mention、Brand24（品牌提及监控）；Ahrefs、Semrush（反向链接）；Visualping、Distill（单页变化监控）

    现有方案的缺陷

    品牌监控只告诉你「被提到了」，不判断提到的价格和功能对不对；反向链接工具不读页面内容；单页监控得自己一个个加，而且是盯别人页面变没变，不是对照你当前的真实价格；没有人帮你盯「你引用的别人产品文档」变了

    解决方案

    先录入一份「产品事实表」（当前价格档、有无免费版、功能名、域名、Logo），自动从你的定价页同步。然后用反向链接数据和搜索找出所有提到你产品的页面（目录站、测评、你自己的博客），逐页抽取价格和功能说法，与事实表对比，列出过期项并附上目录站的修改入口或联系方式。反方向：登记你文章里依赖的第三方文档页面，对方帮助页一改就提示你哪几篇文章可能要改。

    MVP

    网页版：输入域名和定价页地址，抓取前 100 个引用页面，表格列出「页面、写的价格、当前价格、是否过期、修改链接」；每月复查一次并发邮件。第三方文档监控先支持手动加 20 个网址。

  4. 痛点

    公开榜单比的是通用题目，但 HN 讨论里大家发现「最好的代理外壳取决于你的问题」：针对自己领域裁剪工具和预算的外壳又快又便宜；有人团队装了 80 到 100 个技能插件，改一行都要等很久；OpenAI 模型在某些外壳里会说任务太难而放弃，加一句提示词就好了。开发者在 Claude Code、Codex、Cursor 和各种开源外壳之间来回换，却没法用自己的代码库比出结论，花在检查代理输出上的时间比写代码还多。

    目标用户

    每月在 AI 编程上花数百美元的独立开发者和小团队技术负责人；要给团队统一选工具和模型的工程经理；做代理外壳和插件的开发者。

    现有方案

    SWE-bench、Terminal-Bench 等公开榜单；Relay（同一任务让 Claude Code 和 Codex 比赛，保留通过测试的结果）；Kiln harness-tuner（调外壳的提示词和工具）；各代理自带的用量统计

    现有方案的缺陷

    公开榜单不是你的代码和技术栈；Relay 类工具是逐个任务挑结果，不给长期结论；没有把「通过率、每次花费、耗时、人工返工」放在一起比；插件和技能装多了拖慢多少，没人量过

    解决方案

    从你仓库的历史提交里自动挑出 20 到 50 个已有测试覆盖的小改动，回退代码生成「题目」；在隔离容器里用不同的代理外壳 × 模型 × 插件配置分别去做，跑真实测试判定通过，记录 token 花费、步数和时间。输出一张排行榜和建议：日常小改用哪个组合、大改用哪个、哪些插件可以关。每次换新模型时一键重跑。

    MVP

    命令行工具：支持 Claude Code、Codex CLI、一个开源外壳；从 git 历史生成 20 道题；本地 Docker 跑测试；生成 HTML 报告（通过率、平均花费、平均耗时）。用户用自己的订阅或密钥跑。

  5. 痛点

    BugMeNot 运营 23 年后关闭，评论里大家感慨：只是想看一篇公开内容，就被逼注册、被要手机号；临时邮箱常被网站拉黑，验证邮件迟迟不到；有人只试用了 20 分钟 OneNote，想注销账号却被要求先给手机号。用通配邮箱又怕被垃圾邮件轰炸整个域名。Reddit 上也有人受够了「调个图片大小都要注册」的工具站，自己做了免注册的替代品。

    目标用户

    注重隐私、常被注册墙挡住的普通网民和开发者；需要反复试用各种 SaaS 的独立开发者和测评作者；不想把真实手机号交给每个网站的人。

    现有方案

    SimpleLogin、addy.io、Firefox Relay、DuckDuckGo Email Protection、iCloud 隐藏邮件地址、1Password 隐藏邮箱（邮箱别名）；Firefox Relay 美国区手机号掩码；临时邮箱（10 Minute Mail）

    现有方案的缺陷

    别名邮箱和密码管理器各管一半，注册时还要自己来回切；临时邮箱域名大多已被网站拉黑；手机号掩码地区少、很多网站不收虚拟号；没人帮你记「这个账号是为哪个网站开的」，用完也不会提醒你去注销和删数据

    解决方案

    浏览器插件：遇到注册表单时一键填入为该网站新生成的别名邮箱（用自己的域名或服务商的不常见域名）、随机密码和最少必要的假资料，自动点验证邮件。账号清单按「为什么注册、上次使用时间」排序；超过 90 天没用就提醒注销，并按 GDPR 或当地法律自动生成删除数据的请求。付费档加真实运营商临时号码收验证码。

    MVP

    Chrome 插件加转发服务：自动生成别名、填表、点验证链接、存进本地加密清单；一键停用某个别名；附带「删除我的数据」请求模板。先不做手机号。
