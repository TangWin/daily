  1. 目标用户

    刚做出可用产品、卡在第一批付费用户的 solo/小团队；垂直 niche 且自然社区禁自推者

    现有方案

    Lemlist/Instantly, PhantomBuster, startup directories, Build-in-public social

    现有方案的缺陷

    冷邮优化发送量不解决交付物；Reddit 把受众与可获客拆开；目录验证无反馈；缺可回复 vs 仅学习分流

    解决方案

    Conversation-first 获客 OS：诊断结果→一屏交付物邮件；comment-only Reddit 策略；渠道按 clicks-per-post 排名

    MVP

    Web：产品一句话+ICP→10 条交付物冷邮+5 条零提及社区回答模板

  2. 目标用户

    用 Agent 周末出货的 indie；跳过验证步骤的人；需给 Agent 写 abstain 规则的平台方

    现有方案

    idea validator GPTs, interview tools, LangSmith evals, Jev/Milliseconds.ai

    现有方案的缺陷

    验证产品仍是更多生成；缺强制 kill criterion；Agent 默认填空继续；访谈矛盾被平滑

    解决方案

    Pre-execution Decision Gate：用户/痛点/30天证据/失败即停/不可逆面；歧义刹车清单

    MVP

    CLI/VS Code：无 kill criterion 则拒启动 agent session；导出决策日志

  3. 目标用户

    追逾期发票的自由职业者/小工作室；隐私优先记账开发者；需求发现者

    现有方案

    FreshBooks/Wave reminders, Stripe dunning, AI follow-up SaaS

    现有方案的缺陷

    缺真实上下文阶梯；LLM 发明署名；监听停在关键词；云端劝退隐私用户

    解决方案

    本地应收阶梯：结构化渲染身份/金额；模板为主模型为辅；回复资格四象限

    MVP

    导入逾期发票→5 封阶梯稿+确定性校验（禁发明姓名）

  4. 目标用户

    同时试用多家 coding harness 的重度 agent 程序员

    现有方案

    Claude Code, OpenCode, ZCode, Continue/Cursor routing

    现有方案的缺陷

    优秀 UI 与真正 harness 绑死；换模型惩罚不透明；缺统一用量/成本视图

    解决方案

    Harness Control Plane：统一 provider/预算/会话；可插多家底层 harness

    MVP

    本地 daemon+Web UI：对接 2 个 harness 会话列表与 token 用量

  5. 目标用户

    每日 scrum 复盘的工程师；介意云端屏幕捕获的隐私用户

    现有方案

    RescueTime/Timing, meeting note apps, screenshot+OCR

    现有方案的缺陷

    应用级统计无法合并跨工具任务；云端劝退；站会靠记忆/git log

    解决方案

    本地 VLM 工作时间线→standup 三段；默认不出网

    MVP

    macOS 菜单栏本地采样→日终聚类任务→复制到 Slack 模板
